# Estados y evidencia de los proyectos

El catálogo se basa en una revisión privada de artefactos y documentos realizada el 31 de octubre de 2026. Las afirmaciones deben interpretarse en su alcance:

- **Inspección de código o archivos:** demuestra que se localizaron y examinaron, no que funcionen por sí solos.
- **Prueba automatizada:** valida las condiciones cubiertas por esa prueba y versión; no sustituye la prueba física.
- **Prueba real documentada:** vale para la versión, dispositivo y recorrido indicados; no para todo el producto.
- **Prueba con datos ficticios:** sirve para revisar flujos, no para demostrar usuarios o clientes reales.
- **Validación pendiente:** se señala para evitar atribuir éxito a funciones experimentales.

## Clasificación

- **Operativa privada:** existen flujos documentados en entornos propios.
- **Beta técnica:** base implementada, aceptación de campo parcial.
- **RC con bloqueos:** candidata con obstáculos conocidos para distribuirla como producto.
- **Experimental:** investigación o integración todavía no validada de extremo a extremo.
- **Prototipo sin validación actual:** no hay evidencia suficiente del estado operativo presente.

No se atribuyen clientes, ingresos, ahorro medido ni certificaciones que no estén documentados. La publicación de código o APK se decide individualmente según derechos, privacidad y seguridad.
